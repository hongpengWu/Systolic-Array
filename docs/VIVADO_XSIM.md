## Vivado / XSIM Reproduction Guide

This project can be simulated with **Vivado XSIM** as a pure RTL flow.  
No `.xdc`, IP core, block design, or synthesis project is required for functional verification.

## Required Inputs

Before simulation, the following files must exist in `tb/data/`:

- `memA.hex`
- `memB.hex`
- `memI.hex`
- `golden_O.hex`

They are generated by:

```bash
python3 scripts/gen_test_data.py
```

If you use a Conda environment:

```bash
conda activate py38env
python scripts/gen_test_data.py
```

## Reproduction Flow

1. **Generate test data**
   - Run `python3 scripts/gen_test_data.py` from the project root.
   - This creates the matrix/input files used by the testbench.

2. **Run Vivado batch simulation**
   - From the project root, run:

```bash
vivado -mode batch -source vivado/run_xsim.tcl
```

3. **Inspect the result**
   - The simulation log is written to `build/xsim/xsim.log`.
   - A successful run prints:

```text
[TB] PASS: All 16 outputs match golden.
```

The Tcl script [run_xsim.tcl](file:///c:/Users/lenovo/Desktop/trae_tmp/Systolic-Array/vivado/run_xsim.tcl) performs the following steps automatically:

- Checks that all required `.hex` files exist
- Creates `build/xsim/`
- Copies `tb/data/*.hex` into `build/xsim/tb/data/`
- Compiles RTL and testbench with `xvlog`
- Elaborates `tb_top` with `xelab`
- Runs simulation with `xsim -runall`

Copying `tb/data` into the simulation build directory is necessary because the testbench loads files with relative paths such as `$readmemh("tb/data/memA.hex", ...)`.

## Vivado Version Notes

The script is written to work with standard Vivado installations where `xvlog`, `xelab`, and `xsim` are visible from the Vivado batch environment.

For most versions, **no change is required** beyond calling:

```bash
vivado -mode batch -source vivado/run_xsim.tcl
```

If a different Vivado version reports that `xvlog`, `xelab`, or `xsim` cannot be found, there are two supported ways to adapt:

- **Preferred**: Override the tool commands with environment variables before launching Vivado
  - `XSIM_XVLOG`
  - `XSIM_XELAB`
  - `XSIM_XSIM`

- **Direct edit**: Modify the command variables near the top of `vivado/run_xsim.tcl`
  - `xvlog_cmd`
  - `xelab_cmd`
  - `xsim_cmd`

### Example: Windows with explicit tool paths

```powershell
$env:XSIM_XVLOG = "E:\Xilinx\Vivado\2024.2\bin\xvlog.bat"
$env:XSIM_XELAB = "E:\Xilinx\Vivado\2024.2\bin\xelab.bat"
$env:XSIM_XSIM  = "E:\Xilinx\Vivado\2024.2\bin\xsim.bat"
vivado -mode batch -source vivado/run_xsim.tcl
```

### Example: Linux with explicit tool paths

```bash
export XSIM_XVLOG=/tools/Xilinx/Vivado/2024.2/bin/xvlog
export XSIM_XELAB=/tools/Xilinx/Vivado/2024.2/bin/xelab
export XSIM_XSIM=/tools/Xilinx/Vivado/2024.2/bin/xsim
vivado -mode batch -source vivado/run_xsim.tcl
```

If your Vivado version already exposes these commands in batch mode, these overrides are not needed.

## Reproduction Notes

During reproduction on Vivado `2024.2`, two practical issues needed attention:

- **Vivado Tcl command invocation**
  - `xvlog`, `xelab`, and `xsim` should be launched with `exec` from Tcl instead of being called as Tcl commands directly.

- **Relative testbench file paths**
  - The testbench uses `tb/data/*.hex` relative paths.
  - Running from `build/xsim/` therefore requires copying the generated hex files into `build/xsim/tb/data/`.

These details are already handled by `vivado/run_xsim.tcl`.
